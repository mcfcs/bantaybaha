Bantay-Baha code guide: library and dashboard

Every code block of the bantay package (the pipeline: one module per layer) and of the dashboard in app/: what it does, how, and why it was written that way. The data-download scripts, the build entry point, the benchmarks, the document generators and the tests are in the full code guide. Line numbers refer to the code as of the date of this PDF; if a function has moved, search for its name.

1. The bantay library

bantay/__init__.py only holds the package docstring. Every module below is imported by scripts/build.py, and some by the dashboard, the benchmarks and the results scripts.

1.1 bantay/config.py

Shared paths, constants and the missing-input registry.

Block Lines Explanation
Paths ROOT ... APP_DATA 12-17 Every folder the pipeline uses, built from the package location: raw inputs, cached intermediates (interim), outputs (processed), reviewed crosswalks, and the small files the dashboard reads (processed/app).
BBOX, CRS_M 19-20 The Philippine bounding box (lon/lat) and the metric projection used for distances and buffers (UTM 51N).
WEEK_FREQ, FIRST_WEEK, LAST_WEEK, MODEL_END 23-25 DOH weeks end on Sunday; the panel spans 2016-01-10 to 2021-01-10. MODEL_END (2019-12-29) is the last week any model trains on or is scored on, because 2020 reporting collapsed under COVID-19.
STORMS 28-33 The four backtest typhoons: local name, international name, season, landfall date and the folder name used by the GEE downloads.
S1_AFTER_DAYS 37 10: a Sentinel-1 flood map uses images up to 10 days after landfall, so it is known only from the DOH week containing landfall + 10 days. Features must not use it earlier. Must match S1_AFTER in download_gee.py.
QUANTILES 40 The 23 quantile levels of the CDC FluSight forecasting hub (0.01, 0.025, 0.05, 0.10 ... 0.95, 0.975, 0.99).
week_ending() 43-49 Maps any date (or column of dates) to the Sunday that ends its DOH week. Used whenever daily rain or storm times are joined to weekly cases.
_STATUS_FILE, _load_status() 54-60 data/processed/status.json holds one line per input: available or not, a detail, and when it was checked.
record() 63-68 Writes or updates one input's status.
status() 71-72 Returns the whole status dict (the build prints it at the end; the dashboard shows it on Data & caveats).
missing() 75-78 Prints a warning and records the input as missing; returns None so callers can write return missing(...).
have() 81-90 Checks that paths exist (and, for a folder, that it holds a matching file), records the result, returns True/False.
_rel() 93-95 A path relative to the repo when it lies inside it, else as given, so have() can record inputs that live outside the repo (e.g. tests' temporary files) instead of failing.
ensure_dirs() 98-100 Creates the output folders.

1.2 bantay/units.py

Builds the 85 harmonised 2016-2020 provinces and the crosswalks into them. Needed because the dengue file has 126 reporting units (provinces mixed with cities) and today's boundary file (COD-AB) uses post-2020 boundaries.

Block Lines Explanation
Paths 20-23 The COD-AB geodatabase, the two crosswalk CSVs, and the unit polygons output.
MERGE 26-27 Undoes post-2020 changes: Maguindanao del Norte/Sur back to Maguindanao (split 2022), the Special Geographic Area back to Cotabato (created 2024 from Cotabato barangays), City of Isabela into Basilan.
SYNTHETIC_ID 29 Maguindanao has no single current code, so it gets a clearly synthetic id.
DENGUE_FIX, DENGUE_CITY_PROVINCE 32-34 Spelling and old-unit fixes for the dengue file (NUEVA VISCAYA, SISQUIJOR, NORTH COTABATO, BASILIG = Bislig; MAGUINDANAO via Maguindanao del Norte; MANILA = NCR First District) and the one ambiguous city (NAGA CITY is in Camarines Sur, from its Region V label).
norm() 37-41 Normalises a place name for matching: strips accents (Las Piñas -> LASPINAS), parentheses, "City of"/"City" and anything not a letter.
read_adm() 44-48 Reads one COD-AB level (1 = region, 2 = province, 3 = municipality) straight from the zip; records COD-AB as missing (and returns None) if the zip is absent.
_unit_name() 51-55 Gives an ADM2 name its harmonised unit name and the rule used.
build_adm2_crosswalk() 58-65 ADM2 -> unit table. A unit's id is the official code of the member that shares its name, or the synthetic id.
build_dengue_crosswalk() 68-92 Matches each dengue unit to COD-AB: city units are looked up as cities first (so QUEZON CITY is not Quezon province), then province names, then municipality names; each match is folded into its unit. Ambiguous matches get a note.
write_csv_with_header() 95-100 Writes a CSV preceded by # comment lines that document its source and rules (the repo rule for hand-reviewed tables).
read_crosswalk() 103-104 Reads a crosswalk, skipping the comment lines, as text (codes keep leading zeros).
build_crosswalks() 107-137 Builds both crosswalks once and reuses them afterwards (unless --force), because they were reviewed by hand. Returns None, None when COD-AB or the dengue file is missing. Records how many dengue units matched.
check_psgc() 140-154 If the PSA PSGC Excel is downloaded, checks every COD-AB province code against it. Optional; skipped when absent.
build_units_geometry() 157-172 Dissolves ADM2 polygons into the 85 unit polygons, repairs invalid geometry, simplifies to ~50 m (small enough to process fast, finer than the 100 m rasters) and saves units.gpkg.
load_units() 175-178 Loads the unit polygons, building them if needed.
adm3_with_units() 181-187 Municipality polygons with their unit, for the municipal access results, the municipality raster and Sentinel-1 per municipality.

1.3 bantay/dengue.py

The forecast target and the population used to turn cases into incidence.

Block Lines Explanation
DENGUE, CENSUS 12-13 The two input files.
weeks() 16-17 The Sundays from 2016-01-10 to 2021-01-10 (262 weeks).
load_dengue() 20-28 Reads the DOH file, skipping row 2 (HXL tags), stripping stray spaces from names, checking that every date is a Sunday, and dropping deaths (2016 deaths are implausible).
unit_week_cases() 31-45 Builds the full unit x week grid: sums the member reporting units of each harmonised unit and keeps the total only if every member reported that week, so a missing city never looks like zero cases.
unit_population() 48-77 2020 census population per unit. The census's municipal codes are the old 9-digit PSGC and don't join to COD-AB for cities or post-2022 Maguindanao, but its Province column already places cities in their province, so units are matched on that column by name, with fixes for the NCR districts, SGA and City of Isabela.

1.4 bantay/storms.py

Typhoon tracks from IBTrACS: wind radii, swaths, shifted tracks and weekly exposure.

Block Lines Explanation
NM_KM, IBTRACS, R34, COLS 18-22 Nautical miles to km, the file, the four 34-knot radius columns, and the columns read.
load_ibtracs() 25-34 Reads Western Pacific tracks for 2016-2020 near the Philippines (main tracks only) and picks one wind speed per fix (US, else WMO, else Japan).
gale_radius() 37-48 Radius of gale-force winds per fix: the largest US 34-kt quadrant, else Japan's 30-kt radius, else a fixed 150 km; fixes below gale strength get no radius. Keeps which source was used. Why: the US radius is missing on 15-58% of the fixes of the backtest storms.
storm_track() 51-61 Returns the fixes of one backtest storm (by name and season) or any storm id, in time order.
shift_track() 64-70 A "what if" track: the same storm moved by dlat/dlon degrees (and optionally in time). Used for the swath and the map.
interpolate() 73-78 Fills in hourly positions between the 3-hourly fixes, so swaths have no gaps.
swath() 81-93 The area that saw gale-force winds: the union of circles of the gale radius around every hourly position (in metres).
track_line() 96-97 The track as a line (for maps).
unit_week_exposure() 100-134 For every unit and week 2016-2020: the closest any storm came, whether the unit was inside a gale radius, the strongest wind within 300 km, and how many storms passed within 300 km. These become forecast features.
origin_exposure() 137-153 The forecast's 4-week storm features at a forecast origin (storm_gale_4w, storm_wind_4w, storm_dist_4w), computed exactly as the panel and forecast.base_features compute them, from the fixes in the 4 DOH weeks ending at the origin. No fix after the origin week is used.
shift_storm() 156-163 The whole IBTrACS table with one backtest storm's fixes moved; every other storm unchanged. Feeding it to origin_exposure() scores a shifted track with the same rules as training.

1.5 bantay/rain.py

Daily rainfall grids to weekly rainfall per province.

Block Lines Explanation
CHIRPS_DIR, IMERG_DIR 18-19 Input folders.
zonal_weights() 22-40 A sparse matrix saying which grid cells belong to which province (cell centre inside the polygon, land cells only), each row summing to 1. Tiny islands with no cell centre get their nearest land cell. Built once, reused for every day.
apply_weights() 43-50 Multiplies a stack of daily grids by the weights: province mean rainfall per day, ignoring missing cells.
_grid_transform() 53-58 Builds the pixel-to-coordinate transform from the grid's centre coordinates, and notes whether latitude runs upwards (then the grid is flipped).
nearest_cells() 61-68 For a list of points (river reaches), the nearest land cell, via a KD-tree.
chirps_daily_units() 71-100 Reads each CHIRPS year file (with the pure-Python scipy NetCDF reader, because the netCDF4 library is blocked on some Windows machines), converts its julian-day time axis to dates, and returns daily province rainfall; optionally also the rainfall at each river reach.
imerg_daily_units() 103-122 Same for the IMERG monthly GeoTIFF stacks from Earth Engine (one band per day).
weekly() 125-139 Daily to DOH weeks: Monday-Sunday total (_7d), Friday-Sunday total (_3d) and wettest day (_max1d).

1.6 bantay/rivers.py

Rain routed downstream, so a province at a river mouth "feels" rain that fell upstream.

Block Lines Explanation
HR_ZIP, HR_LAYER 15-16 The HydroRIVERS Australasia shapefile.
load_reaches() 19-35 Reads river reaches in the Philippine box and assigns each to the unit containing its midpoint (reaches just off the coastline go to the nearest unit within 2 km). Sorted by upstream area, which puts every reach before the reaches downstream of it.
accumulate() 38-47 Walks reaches from upstream to downstream, adding each reach's rain volume (rain x local catchment area) to the next reach down. Dividing by upstream area gives the average rain over everything upstream of each reach.
unit_week_river() 50-69 Weekly version per unit: discharge-weighted average of upstream rain over the unit's reaches (river_up_7d) and how much more that is than the unit's own rain (river_excess_7d).

1.7 bantay/grids.py

Population grids aligned with WorldPop (100 m), so population, flood and hazard line up cell for cell.

Block Lines Explanation
Constants 17-20 WorldPop file, the unit-id raster, the 1 km population cells, and the processing block size.
fresh() 23-27 True if a cached file exists and is newer than every input it was built from (e.g. units.gpkg), so a changed input triggers a rebuild.
unit_index() 30-33 Gives each unit a small integer code (1-85) for rasters; 0 means outside every unit.
build_unit_raster() 36-54 Burns the unit polygons into a raster on the exact WorldPop grid, block by block (the full grid is 230 M cells). Reused while it is fresh().
iter_blocks() 57-68 Walks several aligned rasters together, one block at a time, to keep memory low.
worldpop_clean() 71-74 Turns nodata and negative values into 0 people.
unit_population_worldpop() 77-87 Population per unit from WorldPop; the fallback when the census table is missing.
build_pop_cells() 90-136 Sums WorldPop into ~1 km cells (369,121 cells, 109 M people), gives each its unit (centre cell, or any unit in the block for coastal cells) and its municipality (containing polygon, else nearest). These are the "people" the access model routes to hospitals. Cached in pop_cells_1km.parquet.
HRSL, HRSL_CELLS, HRSL_ROWS 141-144 The two Meta HRSL 2020 layers (children under 5, people aged 60+), their cache, and how many rows of the ~30 m rasters are read at once.
_hrsl_block_sums() 147-177 Sums one HRSL raster (read inside its zip, top to bottom) onto the same 1 km blocks build_pop_cells() uses: each 30 m pixel goes to the block holding its centre. Also returns the total and the people outside the WorldPop grid.
build_vulnerable_cells() 180-212 Under-5 and 60+ people per population cell (same rows as the cells), both layers read in parallel, cached in pop_cells_hrsl.parquet. People in blocks without a WorldPop cell are dropped and the kept share is recorded; a layer whose zip is missing stays NaN.
ADM3_RASTER, adm3_index() 217-222 The municipality raster's path and its stable code per municipality (1..n; 0 = outside).
build_adm3_raster() 225-250 Burns the COD-AB municipality polygons onto the WorldPop grid (uint16 codes), block by block, only rasterising the polygons that touch each block; written to .part.tif and renamed. Used for Sentinel-1 per municipality.
_box() 253-256 A shapely box from raster-window bounds (for the spatial-index query above).

1.8 bantay/flood.py

Flood exposure: UP NOAH hazard maps (static), Copernicus EMS and Sentinel-1 (observed, per typhoon).

Block Lines Explanation
NOAH, EMS, S1, RPS 28-31 Input folders and return periods (5-yr, 25-yr).
hazard_raster_path() 34-35 Where the national hazard raster for a return period is cached.
_nk() 40-41 Name normaliser for NOAH file names.
noah_file_units() 44-68 Works out which units each NOAH zip covers, from its shapefile names (CamelCase province names or old 9-digit codes) including multi-province files (Mindoro, Metro Manila, pre-split Maguindanao).
_hazard_col() 71-72 Finds the hazard-class column (usually Var).
build_hazard_raster() 75-123 One national raster per return period on the WorldPop grid: 255 = no map, 0 = mapped and safe, 1-3 = low/medium/high hazard. Starts all-255, then for each province file marks its units as mapped and burns in the hazard polygons (highest class wins). Rebuilt only when a NOAH file or the unit polygons are newer. Why 255: "no map" must stay missing, never become "no hazard".
unit_hazard_shares() 126-156 Share of each unit's people in any hazard class and in the high class; NaN when less than half the unit's people are on a mapped area (11 units have no 25-yr map).
ems_observed_flood() 161-179 Reads the observed-flood polygons from the Copernicus EMSR312 packages (Ompong; first map and later monitoring map).
s1_tiles() 184-186 Lists a storm's Sentinel-1 flood tiles.
_tile_cell() 189-192 The nominal 1-degree cell of a tile, read from its name (s1flood_121E_17N.tif).
_s1_zone_sums() 195-220 The shared counter: resamples each tile of a storm onto the WorldPop grid and adds up, per zone code (unit or municipality), the pixels the radar saw, the flooded pixels and the people in them. With crop, each tile is read only over its 1-degree cell, so the ~2-pixel overlap between neighbouring tiles is counted once.
s1_unit_flood() 223-237 Per unit: share of the land Sentinel-1 saw that newly flooded, and people in that flood (WorldPop). Uncropped, as the panel was built.
s1_adm3_flood() 240-278 The same per municipality for every storm with tiles (flood share, people in flood, and seen_frac, the share of the municipality the radar saw), on the municipality raster with cropped tiles. Written to s1_adm3.parquet by the scenarios stage.
s1_flood_lookup() 281-303 Loads a storm's tiles into memory once and returns a function that answers "flooded or not" for millions of points at once with array indexing (road midpoints, friction cells).

1.9 bantay/panel.py

Step 0: the one table every model reads (85 units x 262 weeks).

Block Lines Explanation
PANEL, S1_BY_STORM, CARD 15-17 Output files: the panel, the per-storm Sentinel-1 table, and the panel's data card.
COLUMNS 19-44 Every panel column with its source and meaning; it drives the data card and guarantees every documented column exists (NaN when its input is missing).
_newest(), cached() 47-61 A small cache: reuse an intermediate in data/interim/ if it is newer than all its inputs, else rebuild it. Missing inputs (None) are never cached, so they are retried next time.
rain_layers() 64-89 CHIRPS weekly rain plus river routing in a single pass over CHIRPS (the slow part), and IMERG weekly rain; both cached.
static_layers() 92-98 Builds the unit raster and NOAH hazard rasters (first run only) and returns hazard shares per unit.
s1_layers() 101-117 Sentinel-1 flood per unit, placed on 4 weeks starting with the DOH week that contains landfall + S1_AFTER_DAYS (the week the map is complete), not the landfall week, so no feature at a forecast origin uses radar taken after it. Writes the per-storm values to s1_unit_storm.parquet. Rolly and Ulysses landed 10 days apart, so their windows overlap; the larger flood per unit-week is kept.
build_panel() 120-171 Assembles the panel: the full unit x week grid, cases, population (census, else WorldPop), incidence per 100,000, storm exposure (weeks with no storm nearby get "far": 2000 km, no hit), rain, rivers, hazard, the storm-x-hazard interaction and Sentinel-1. Writes the parquet and the data card.
write_card() 174-187 Writes panel_card.md: coverage of every column and the status of every input.
load_panel() 190-191 Reads the panel.

1.10 bantay/leadlag.py

Layer 2: which provinces' dengue rises first, and which follow.

Block Lines Explanation
TAU_MAX, MIN_T, EDGE_COLS 16-19 Longest lead considered (3 weeks); the fewest differenced weeks a graph is learned from (52; shorter windows, such as the catalogue's 2017 storms, get an empty graph); the columns of an edge table.
prepare() 22-31 For a training window: log incidence, minus the same week a year earlier (removes the shared rainy-season peak, which would otherwise link every pair), drops units with over 10% missing weeks, fills short gaps, standardises each series.
_bh() 34-41 Benjamini-Hochberg false-discovery correction of p-values.
xcorr_graph() 44-63 The simple baseline: correlation between province i lagged 1-3 weeks and province j now; keeps positive links that survive false-discovery control. Gives 4,265 links on 2016-2019, mostly the shared 2019 epidemic.
pcmci_graph() 66-91 PCMCI+ (Tigramite, partial correlations): a link i -> j is kept only if it holds after conditioning on j's own past and other provinces. Keeps lagged links between different provinces with q < 0.05 (on pure noise, PCMCI+ alone returned 60-90 false links). Optional bootstrap gives each link a confidence.
node_metrics() 94-110 PageRank on the reversed graph (high score = many provinces follow you: a sentinel), number of leaders and followers, and Louvain communities (provinces that move together). A sentinel is a top-ranked unit (top 10%, at least 5) with at least one follower.
learn() 113-123 Runs the above for a window ending at a given date and returns links, per-province metrics and a summary (series, weeks, link count).

1.11 bantay/forecast.py

The forecaster, its baselines, the scores, the rolling-origin test, the calibration of R and the benchmark scoring.

Block Lines Explanation
Q, IQ50, HORIZONS, SURGE_PCTL 30-33 The 23 quantiles, the index of the median, horizons 1-4 weeks, and the surge definition (above the unit's 90th percentile).
GROUPS, GRAPH_FEATURES, ENV_FEATURES, MODELS 35-48 Every feature, grouped into drivers shown on the dashboard (recent cases, season, rain, river, storm/flood, outbreak graph, unit). The built-in models: xgb (all features), the ablations xgb_nograph (no graph features) and xgb_noenv (no rain, river, storm or flood features), and naive.
CAL_MIN_ROWS, R_CLIP, CUM4_FILE 52-54 R is recalibrated only once 850 past surge outcomes exist (10 weeks x 85 units); the clip of calibrated R; the file the forecast stage saves the rolling-origin surge forecasts to.
ENSEMBLE, BENCH_GLOB, BENCH_MODELS, BAND 55-60 The median ensemble's name, the benchmark file pattern, the benchmarks allowed into the ensemble (chronos2, tabpfn_ts, mpnn_lstm; any other bench_* file is a variant and is ignored here), and the fan-chart quantile levels.
base_features() 65-102 Features known at the forecast week t (never later): log incidence now and 1-3 weeks ago, 4- and 8-week averages, 4-week change, rain lags and 4/8-week totals, river rain, storm exposure over the last 4 weeks, hazard shares, Sentinel-1 flood, population, and the province as a category. Features whose source is missing are left out.
target_frame() 105-116 Adds the target for horizon h (log incidence at t+h), the same week last year (the seasonal-naive value) and its 5-week centred average, and the week-of-year of the target.
cum4_frame() 119-127 Target = total incidence over the next 4 weeks (used for the surge probability R).
graph_features() 130-150 For each follower province, its leaders' recent rise and year-on-year anomaly (weighted by link strength), and the number of leaders. Uses only leader values up to week t.
feature_columns() 153-159 The feature list, with or without the graph features or the environmental features (the ablations).
fit_quantile_model() 164-169 One XGBoost model that outputs all 23 quantiles at once (quantile loss), 150 trees, depth 4.
predict_quantiles() 172-173 Predicts and sorts each row's quantiles (so they never cross).
usable() 176-178 Drops features that are empty in the training rows.
seasonal_naive() 181-185 The bar to beat: "same week last year", with a range taken from its past errors.
prob_exceed() 188-200 Turns 23 quantiles into the probability of exceeding a threshold, by interpolating the quantile curve.
surge_thresholds() 203-208 Each unit's 90th percentile of 4-week incidence, computed from training weeks only.
to_cases() 213-214 Back from log incidence per 100,000 to case counts.
wis() 217-227 The weighted interval score (Bracher et al., 2021): rewards narrow ranges that contain the truth and penalises misses in proportion to how far out they are.
coverage() 230-233 Whether the outcome fell inside the 50% or 90% range.
refit_dates() 238-239 Refit every 13 weeks from January 2018 to December 2019 (8 refits).
rolling_origin() 242-282 The honest test. At each refit date: re-learn the graph and thresholds on past data, train on rows whose target is before the refit date, forecast every week until the next refit. Per horizon it fits xgb, xgb_nograph and xgb_noenv (the surge model only the first two) and adds the seasonal naive; when a window's graph has no links, xgb equals xgb_nograph, so that fit is skipped. The 4-week model gives the raw surge probabilities R_xgb, R_xgb_nograph.
score_rows() 285-297 WIS, absolute error and 50%/90% coverage on case counts for any set of models' quantiles; a row with a missing quantile scores NaN, so models can be compared on the same rows.
score() 300-321 Scores every forecast of the built-in models, plus an online conformal 90% band (built only from errors of forecasts already past) as a check.
summarise() 324-345 Averages by horizon and overall, every model on the same rows: WIS, relative WIS vs seasonal naive, graph vs no-graph, with vs without environment, coverage.
SurgeCalibrator 348-362 An isotonic map from raw R to the observed surge frequency, fitted on past forecasts only; keeps how many outcomes it used and the last target week it saw.
SurgeCalibrator.__init__() 352-354 Fits the isotonic regression (increasing, clipped to 0-1).
SurgeCalibrator.__call__() 356-362 Maps raw R to calibrated R (NaN stays NaN, result clipped to R_CLIP).
fit_calibrator() 365-373 Builds a calibrator from rows whose outcome is known at a given date (target week on or before it, the same rule as model training); None with fewer than CAL_MIN_ROWS outcomes or only one class.
cum4_eval() 376-401 The evaluation version: for every forecast origin t, calibrates that origin's R with a calibrator fitted on forecasts whose 4-week window ended by t (expanding window), so calibrated R never uses a later outcome; rows before 850 past outcomes keep the raw R. Asserts there is no leakage.
RELIABILITY_BINS, _reliability() 404-409 Reliability table: in bins of R, the mean R and how often a surge happened.
_brier() 412-413 Brier score of a probability column.
surge_calibration() 416-444 Brier score of raw and calibrated R, the base rate, the climatology Brier, which origins stayed uncalibrated, and the reliability table before and after calibration.
surge_calibrator() 447-462 The production version for the scenarios: a calibrator fitted on every saved rolling-origin surge forecast (eval_cum4.parquet) whose outcome is known by the model's training end. None (R stays raw, recorded) if the file is missing or there are too few outcomes.
calibrate_R() 465-473 Scenario hook: keeps the model probability as R_raw, sets R to the calibrated value (raw if there is no calibrator) and flags R_calibrated.
eval_quantiles() 478-485 The rolling-origin horizon 1-4 rows with every built-in model's 23 quantiles, saved so benchmarks can be scored and ensembled later without refitting XGBoost.
_key() 488-491 The join key (unit, origin week, horizon) in one fixed set of types.
load_bench() 494-540 Reads each bench_<model>.parquet in BENCH_MODELS (and its .json metadata), checks the schema, drops invalid or duplicate rows and aligns it to the evaluation rows. Other names are recorded as ignored variants; a bad file is skipped with a warning, never fatal.
evaluate_models() 543-584 Scores xgb, its ablations, the naive baseline, every benchmark and the median ensemble (element-wise median of the 23 quantiles over xgb and the benchmarks, only where all exist) on the same rows. Returns the model x horizon table, fan-chart bands for the benchmarks and the ensemble, and metadata.
fit_at() 589-604 For the scenarios: learns the graph and the surge thresholds and trains the graph model for every horizon and the 4-week model on data up to a storm's forecast origin (never past 2019).
predict_at() 607-632 Forecasts every province from that week; optional overrides replace the storm features (one row per unit); computes raw R and the per-driver SHAP contributions shown on the dashboard.

1.12 bantay/access.py

Layer 3: travel time to the nearest hospital over roads and ferries, before and during a storm, by two methods: a road and ferry network (the primary method) and a raster over the MAP friction surface (the check). The gap between them is reported as uncertainty.

Block Lines Explanation
PBF, ROADS, SPEED 35-40 The OpenStreetMap file, the cached road graph, and assumed travel speeds per road class (links at 80% of their road). Speeds are a tunable assumption, tested in the sensitivity analysis.
WALK_KMH, MAX_SNAP_KM, LAT0 42-43 Walking 5 km/h from a home to the road, at most 5 km; a reference latitude for fast km conversions.
_xy(), _hav_km() 46-54 Coordinates to km (for nearest-node search) and great-circle distance.
build_road_graph() 59-96 Reads OSM roads through GDAL, finds junctions as coordinates shared by two or more roads (OSM roads share nodes there), cuts roads into segments between junctions, and stores each segment's length, speed and midpoint. 1.72 M junctions, 2.13 M segments, cached.
_nhfr() 101-122 Reads the DOH facility registry if downloaded by hand: finds latitude/longitude and type columns and keeps hospitals.
load_hospitals() 125-155 NHFR if available, else the fallback: OSM hospitals plus NOAH facilities whose names say hospital or medical center, with duplicates within 300 m removed (2,199). Labelled as a fallback everywhere.
load_ferries() 160-169 The 108 RoRo routes; crossing time plus half the time between departures (capped at 12 h), and a straight line between ports for storm checks.
Network 174-225 The routable road and ferry network.
Network.__init__() 177-200 Snaps hospitals and population cells to the nearest road junction (within 5 km; a cell further from a road has no route) and ferry ports to junctions within 25 km (their coordinates are coarse), adding the port access at 30 km/h to the crossing time.
Network.road_hours() 202-207 Travel hours per segment, with optional speed multipliers (0 = road closed).
Network.solve() 209-225 Builds a sparse graph of roads and ferries (keeping the fastest of parallel edges) and runs one multi-source Dijkstra from all hospitals at once: hours from every junction to its nearest hospital. Adds the walk from each population cell.
cut_off() 228-230 A cell is cut off if it had a route before the storm and now has none, or its trip at least doubled and grew by more than an hour.

3. Glossary

Term Meaning
R Surge probability: chance the next 4 weeks' incidence exceeds the province's 90th percentile.
Calibrated R / R raw The model's raw probability (R_raw) mapped by an isotonic fit to how often surges really happened, using past forecasts only. The calibrated value is R, used for P and the tiers.
A Access loss: share of a province's people who lose their route to a hospital in the storm.
Network / raster method Two ways to compute travel time: the road and ferry graph (main) and the MAP friction surface (check). A_lo / A_hi (and P_lo / P_hi) span the two.
P Priority = R x A.
Tier The provisional action rule: deploy mobile clinics, pre-position supplies, or monitor.
Unit One of the 85 harmonised 2016-2020 provinces (NCR is split into its 4 districts).
Incidence Cases per 100,000 people.
Rolling origin Testing a forecaster as if in real time: train on the past, forecast forward, move the cut-off forward.
WIS / relative WIS Weighted interval score of a forecast range (lower is better); relative WIS < 1 means better than the seasonal-naive baseline.
Seasonal naive "Same week last year", the baseline forecast.
Ablation The same model with a group of features removed (no graph, no rain/river/storm/flood), to see what that group adds.
Benchmark / median ensemble Outside models scored on the same rows (Chronos-2, TabPFN-TS, MPNN-LSTM); the ensemble is the median of their and XGBoost's quantiles.
Quantile A forecast at a probability level; 23 of them describe the full range.
Coverage How often the truth falls inside a stated range (90% range should catch ~90%).
Brier score Error of a probability forecast (lower is better).
PCMCI+ A causal-discovery algorithm for time series that keeps a link only if it survives conditioning on other series and their pasts.
FDR / Benjamini-Hochberg A correction that controls the share of false links when testing thousands of pairs.
Sentinel / PageRank / Louvain A province others follow (scored with PageRank); groups of provinces that move together (Louvain).
Gale swath Area that saw gale-force (34-knot) winds along the track.
Shifted track The same storm moved north/south/east/west, for "what if" scenarios.
Storm catalogue Every other 2016-2020 storm whose gale swath reached land, scored on its observed track with the NOAH proxy.
NOAH hazard proxy Using flood-hazard maps instead of observed flood to decide which roads close; an upper bound.
Sentinel-1 Radar satellite that sees flood through clouds; our observed-flood source (a lower bound).
EMS Copernicus Emergency Management Service flood maps; used to check Sentinel-1.
HRSL Meta's High Resolution Settlement Layer: counts of children under 5 and people aged 60+, used for the vulnerable people cut off.
Dijkstra Shortest-path algorithm; run from all hospitals at once to get each place's nearest-hospital time.
IRR / distributed lag Incidence rate ratio (1 = no change); a distributed-lag model fits several weeks of lagged rain together.
Event study / placebo Comparing cities inside and outside a storm's swath around landfall; the weeks before landfall should show no difference.
SUS System Usability Scale: ten statements scored 0-100; about 68 is average.
Crosswalk A table mapping one set of place codes or names onto another.
Manifest data/raw/MANIFEST.csv: every raw file with size and checksum.
