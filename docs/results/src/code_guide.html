1. The big picture

Bantay-Baha answers two questions for a typhoon track: where will dengue surge (R) and who loses their route to a hospital (A). Priority is P = R x A.

 download_data.py / download_gee.py / sync_data.py  ->  data/raw/            (21+ sources, MANIFEST.csv)
                                                          |
 scripts/build.py                                         v
   crosswalk  units.py          126 dengue units -> 85 harmonised provinces  (data/crosswalks/, units.gpkg)
   panel      panel.py          one row per province per week: cases, rain, rivers, storms, flood   (panel.parquet)
                 uses dengue.py, storms.py, rain.py, rivers.py, grids.py, flood.py
   leadlag    leadlag.py        PCMCI+ lead-lag graph, sentinels, communities
   forecast   forecast.py       quantile XGBoost, rolling-origin test, WIS scores
   scenarios  scenarios.py      for 4 typhoons x 15 tracks: R (forecast) x A (access.py) -> P, tiers
   app        (simplified map)                                                    -> data/processed/app/
                                                          |
 app/streamlit_app.py    reads data/processed/app/ only   v   dashboard
 scripts/make_results.py reads data/processed/            ->  docs/results/ (report, slides, demo script)

Three rules shape the whole codebase:

  • Missing data never stops a build. Every stage checks its inputs with config.have() / config.missing(); missing inputs leave columns empty (NaN) and are listed in data/processed/status.json. Re-running after the files arrive picks them up with no code change. Nothing is ever filled with fake numbers.
  • No look-ahead. Forecasts are tested by rolling origin (train on the past, predict the future, move forward); the graph and thresholds are re-learned inside each training window.
  • Heavy work happens in the build, not the dashboard. The dashboard only reads small pre-computed files, so it answers in seconds.

2. Entry points (.bat files)

File What it does
setup.bat Team setup: creates the venv at %USERPROFILE%\.venvs\bantay-baha (outside OneDrive so it isn't synced), installs requirements.txt, registers the Jupyter kernel, signs in to Google once (earthengine authenticate), then runs scripts/sync_data.py pull to copy data/raw/ from the team bucket. Each step is skipped if already done.
download_data.bat The slow path: same venv setup, then downloads every source from its original website (download_data.py) and, if a GEE project id is given, the Earth Engine sources (download_gee.py). Used to (re)build the bucket.
build.bat Runs scripts/build.py with the venv's Python, passing any stage names through (build.bat panel forecast).
run_app.bat Starts the dashboard: python -m streamlit run app/streamlit_app.py.

3. Getting the data

scripts/download_data.py (open sources)

Downloads every open dataset into data/raw/<source>/ and records each file in data/raw/MANIFEST.csv (source, path, bytes, sha256, url). Safe to re-run: finished files are skipped.

Block Lines Explanation
Constants ROOT, RAW, UA, HDX 23-26 Repo root and raw folder found from the script's own location (works from any working directory). UA is a polite User-Agent; some servers reject Python's default.
STATIC 29-89 The catalogue of single-file sources: source -> [(url, filename)]. Adding a source = adding a line here. HydroRIVERS uses the Australasia (au) file because the Philippines is not in the Asia file.
EMS, NOAH_FOLDERS, NOAH_DOCS 92-94 Sources that need scraping: Copernicus EMS activations (with a filename filter) and the UP NOAH Google Drive folder ids.
CHIRPS_BBOX, CHIRPS_YEARS 98-99 The Philippine bounding box and years for the server-side CHIRPS subset.
PARTIAL 101 Collects single files that failed inside a source that otherwise finished, so one bad file doesn't abort a whole source.
fetch() 104-125 The download primitive. Skips existing non-empty files; streams to name.part and renames only when complete (an interrupted run never leaves a half file that looks finished); retries 3 times with back-off; with binary=True refuses an HTML page (a quota or login page) masquerading as a file.
drive_listing() 128-130 Lists a public Google Drive folder by parsing its embedded-view HTML (no API key needed).
fetch_drive() 133-135 Downloads a Drive file via drive.usercontent.google.com with confirm=t, which skips the virus-scan page Drive shows for files over 100 MB.
pull_static() 138-139 Fetches every (url, filename) of one STATIC source.
pull_ems() 142-149 Scrapes each EMS activation page for *_vector.zip links and downloads the ones matching the filter (EMSR312 delineation packages; all of EMSR478).
pull_noah() 152-165 Downloads the NOAH readme/licence, then every province zip in the 5-yr and 25-yr folders; a failed province is recorded in PARTIAL and the rest continue.
pull_chirps() 168-176 Builds one IRI Data Library URL per year that subsets CHIRPS daily rainfall to the Philippine box on the server, then downloads it as NetCDF.
PULLERS 179 Maps every source name to its puller, so main() can run all of them or a chosen few.
sha256() 182-187 Checksum of a file, read in 1 MB chunks (works for multi-GB files).
write_manifest() 190-205 Merges new rows into MANIFEST.csv; recomputes the checksum only when a file's size changed (avoids re-hashing 7 GB on every run).
main() 208-226 Runs the selected pullers; writes the manifest after each source (an interrupted run keeps what finished); prints failures and exits non-zero if anything failed.
if __name__ == "__main__" 229-230 Command-line entry: source names are optional arguments.

scripts/download_gee.py (Google Earth Engine sources)

Needs a registered Earth Engine project (--project <id>). Pulls IMERG rainfall, the MAP friction surface, Global Flood Database events, a Sentinel-1 scene inventory and the Sentinel-1 flood masks.

Block Lines Explanation
Imports, ROOT, RAW, BBOX 17-32 Same layout as download_data.py; imports its write_manifest so GEE files land in the same manifest.
TYPHOONS, IBTRACS_NAMES 35-41 The four backtest storms: landfall dates (for before/after windows) and their IBTrACS names (to find the track).
WRITTEN 43 Every file written or skipped, collected for the manifest.
download_image() 46-61 Asks Earth Engine for a GeoTIFF of an image over a region at a scale, downloads it (unzipping when EE returns a zip), and records it. Skips files already on disk.
pull_imerg() 64-78 For each month 2016-2020, turns half-hourly IMERG (mm/h) into daily totals (mean x 24) and stacks the days as bands of one GeoTIFF per month.
pull_map_friction() 81-85 Downloads the Malaria Atlas Project 2019 friction surfaces (motorised and walking), about 1 km.
pull_gfd() 88-98 Writes a table of Global Flood Database events that intersect the Philippines (dates, cause, deaths). Context only: it ends in 2018.
pull_sentinel1() 101-120 Lists every Sentinel-1 scene from 24 days before to 14 days after each landfall (no imagery), used to plan the flood mapping.
track_tiles() 123-138 Picks the 1-degree tiles of the Philippine box within ~350 km of a storm's track (reads the local IBTrACS file), so we only process tiles the storm could have flooded.
s1_flood_image() 141-176 The flood-mapping recipe, computed on Google's servers. For each relative orbit (same satellite geometry) that imaged the tile both before and after landfall: before = median VH backscatter of days -30..-3, after = darkest smoothed image of days 0..+10; a pixel is new flood when VH drops by at least 3 dB and ends below -18 dB (water is radar-dark). Floods from all orbits are combined; permanent water (JRC), slopes over 5 degrees and specks under 8 pixels are removed. Output: 1 = new flood, 0 = dry, 255 = no data or sea. Why not plain UN-SPIDER? Its after/before ratio on dB values found almost none of the flood Copernicus mapped at Tuguegarao; sampling showed real 4-10 dB drops that the ratio missed.
STORM_FILTER, pull_s1_flood() 179-198 Loops over storms (or only those given with --storms) and their tiles; builds the flood image per tile and downloads it at 100 m. Tiles no orbit covered are reported as none and skipped.
PULLERS, main block 201-218 Command-line entry: initialises Earth Engine with the project, runs the chosen pullers and writes the manifest per source.

scripts/sync_data.py (team bucket)

Mirrors data/raw/ to and from the private Cloud Storage bucket, so teammates don't redo slow downloads.

Block Lines Explanation
PROJECT, BUCKET, LOCATION, PREFIX 25-28 Where the team's copy lives (Singapore region).
client() 31-39 Makes a Storage client from Application Default Credentials, falling back to the Earth Engine login.
read_manifest(), write_manifest() 42-50 Read/write MANIFEST.csv as a dict keyed by path.
push() 53-76 Creates the bucket if needed (private, uniform access), uploads every manifest file the bucket lacks or has a different checksum for, then uploads the manifest itself.
pull() 79-102 Downloads every file in the bucket's manifest that is missing locally, to .part, checks its sha256 and only then renames it; merges the rows into the local manifest.
main block 105-112 python scripts/sync_data.py pull|push [sources...].

4.2 bantay/units.py

Builds the 85 harmonised 2016-2020 provinces and the crosswalks into them. Needed because the dengue file has 126 reporting units (provinces mixed with 45 cities) and today's boundary file (COD-AB) uses post-2020 boundaries.

Block Lines Explanation
Paths 20-23 The COD-AB geodatabase, the two crosswalk CSVs, and the unit polygons output.
MERGE 26 Undoes post-2020 changes: Maguindanao del Norte/Sur back to Maguindanao (split 2022), the Special Geographic Area back to Cotabato (created 2024 from Cotabato barangays), City of Isabela into Basilan.
SYNTHETIC_ID 29 Maguindanao has no single current code, so it gets a clearly synthetic id.
DENGUE_FIX, DENGUE_CITY_PROVINCE 32-34 Spelling fixes for the dengue file (NUEVA VISCAYA, SISQUIJOR, BASILIG = Bislig, NORTH COTABATO) and the one ambiguous city (NAGA CITY is in Camarines Sur, from its Region V label).
norm() 37-41 Normalises a place name for matching: strips accents (Las Piñas -> LASPINAS), parentheses, "City of"/"City" and anything not a letter.
read_adm() 44-47 Reads one COD-AB level (1 = region, 2 = province, 3 = municipality) straight from the zip.
_unit_name() 50-54 Gives an ADM2 name its harmonised unit name and the rule used.
build_adm2_crosswalk() 57-64 ADM2 -> unit table. A unit's id is the official code of the member that shares its name, or the synthetic id.
build_dengue_crosswalk() 67-91 Matches each dengue unit to COD-AB: city units are looked up as cities first (so QUEZON CITY is not Quezon province), then province names, then municipality names; each match is folded into its unit. Ambiguous matches get a note.
write_csv_with_header() 94-99 Writes a CSV preceded by # comment lines that document its source and rules (the repo rule for hand-reviewed tables).
read_crosswalk() 102-103 Reads a crosswalk, skipping the comment lines, as text (codes keep leading zeros).
build_crosswalks() 106-134 Builds both crosswalks once and reuses them afterwards (unless --force), because they were reviewed by hand. Records how many dengue units matched (126/126).
check_psgc() 137-151 If the PSA PSGC Excel is downloaded, checks every COD-AB province code against it. Optional; skipped when absent.
build_units_geometry() 154-169 Dissolves ADM2 polygons into the 85 unit polygons, repairs invalid geometry, simplifies to ~50 m (small enough to process fast, finer than the 100 m rasters) and saves units.gpkg.
load_units() 172-175 Loads the unit polygons, building them if needed.
adm3_with_units() 178-184 Municipality polygons with their unit, for the municipal access results.

4.3 bantay/dengue.py

The forecast target and the population used to turn cases into incidence.

Block Lines Explanation
DENGUE, CENSUS 12-13 The two input files.
weeks() 16-17 The 262 Sundays from 2016-01-10 to 2021-01-10.
load_dengue() 20-27 Reads the DOH file, skipping row 2 (HXL tags), stripping stray spaces from names, checking that every date is a Sunday, and dropping deaths (2016 deaths are implausible).

4.4 bantay/storms.py

Typhoon tracks from IBTrACS: wind radii, swaths, shifted tracks and weekly exposure.

Block Lines Explanation
NM_KM, IBTRACS, R34, COLS 18-21 Nautical miles to km, the file, the four 34-knot radius columns, and the columns read.
load_ibtracs() 25-33 Reads Western Pacific tracks for 2016-2020 near the Philippines (main tracks only) and picks one wind speed per fix (US, else WMO, else Japan).
gale_radius() 36-47 Radius of gale-force winds per fix: the largest US 34-kt quadrant, else Japan's 30-kt radius, else a fixed 150 km; fixes below gale strength get no radius. Keeps which source was used. Why: the US radius is missing on up to 58% of fixes.
storm_track() 50-60 Returns the fixes of one backtest storm (by name and season) or any storm id, in time order.
shift_track() 63-69 A "what if" track: the same storm moved by dlat/dlon degrees (and optionally in time).
interpolate() 72-77 Fills in hourly positions between the 3-hourly fixes, so swaths have no gaps.
swath() 80-92 The area that saw gale-force winds: the union of circles of the gale radius around every hourly position (in metres).
track_line() 95-96 The track as a line (for maps).
unit_week_exposure() 99-133 For every unit and week 2016-2020: the closest any storm came, whether the unit was inside a gale radius, the strongest wind within 300 km, and how many storms passed within 300 km. These become forecast features.
scenario_exposure() 136-150 The same exposure for one (possibly shifted) track; used to replace the storm features when a track is shifted.

4.5 bantay/rain.py

Daily rainfall grids to weekly rainfall per province.

Block Lines Explanation
CHIRPS_DIR, IMERG_DIR 18-19 Input folders.
zonal_weights() 22-40 A sparse matrix saying which grid cells belong to which province (cell centre inside the polygon, land cells only), each row summing to 1. Tiny islands with no cell centre get their nearest land cell. Built once, reused for every day.

chirps_daily_units() 71-100 Reads each CHIRPS year file (with the pure-Python scipy NetCDF reader, because the netCDF4 library is blocked on some Windows machines), converts its julian-day time axis to dates, and returns daily province rainfall; optionally also the rainfall at each river reach.
imerg_daily_units() 103-122 Same for the IMERG monthly GeoTIFF stacks from Earth Engine (one band per day).

4.6 bantay/rivers.py

Rain routed downstream, so a province at a river mouth "feels" rain that fell upstream.

Block Lines Explanation
HR_ZIP, HR_LAYER 15-16 The HydroRIVERS Australasia shapefile.
load_reaches() 19-35 Reads river reaches in the Philippine box and assigns each to the unit containing its midpoint (reaches just off the coastline go to the nearest unit within 2 km). Sorted by upstream area, which puts every reach before the reaches downstream of it.
accumulate() 38-47 Walks reaches from upstream to downstream, adding each reach's rain volume (rain x local catchment area) to the next reach down. Dividing by upstream area gives the average rain over everything upstream of each reach.
unit_week_river() 50-69 Weekly version per unit: discharge-weighted average of upstream rain over the unit's reaches (river_up_7d) and how much more that is than the unit's own rain (river_excess_7d).

4.10 bantay/leadlag.py

Layer 2: which provinces' dengue rises first, and which follow.

Block Lines Explanation
TAU_MAX 16 Longest lead considered: 3 weeks.
prepare() 19-28 For a training window: log incidence, minus the same week a year earlier (removes the shared rainy-season peak, which would otherwise link every pair), drops units with over 10% missing weeks, fills short gaps, standardises each series.
_bh() 31-38 Benjamini-Hochberg false-discovery correction of p-values.
xcorr_graph() 41-60 The simple baseline: correlation between province i lagged 1-3 weeks and province j now; keeps positive links that survive false-discovery control. Gives 4,265 links, mostly the shared 2019 epidemic.
pcmci_graph() 63-88 PCMCI+ (Tigramite, partial correlations): a link i -> j is kept only if it holds after conditioning on j's own past and other provinces. Keeps lagged links between different provinces with q < 0.05 (on pure noise, PCMCI+ alone returned 60-90 false links). Optional bootstrap gives each link a confidence.
node_metrics() 91-107 PageRank on the reversed graph (high score = many provinces follow you: a sentinel), number of leaders and followers, and Louvain communities (provinces that move together).
learn() 110-117 Runs the above for a window ending at a given date and returns links, per-province metrics and a summary (series, weeks, link count).

4.11 bantay/forecast.py

The forecaster, its baseline, the scores and the rolling-origin test.

Block Lines Explanation
Q, IQ50, HORIZONS, SURGE_PCTL 21-24 The 23 quantiles, the index of the median, horizons 1-4 weeks, and the surge definition (above the unit's 90th percentile).
GROUPS, GRAPH_FEATURES 26-37 Every feature, grouped into drivers shown on the dashboard (recent cases, season, rain, river, storm/flood, outbreak graph, unit).
base_features() 42-79 Features known at the forecast week t (never later): log incidence now and 1-3 weeks ago, 4- and 8-week averages, 4-week change, rain lags and 4/8-week totals, river rain, storm exposure over the last 4 weeks, hazard shares, Sentinel-1 flood, population, and the province as a category. Features whose source is missing are left out.
target_frame() 82-93 Adds the target for horizon h (log incidence at t+h), the same week last year (the seasonal-naive value) and the week-of-year of the target.
cum4_frame() 96-104 Target = total incidence over the next 4 weeks (used for the surge probability R).
graph_features() 107-127 For each follower province, its leaders' recent rise and year-on-year anomaly (weighted by link strength), and the number of leaders. Uses only leader values up to week t.
feature_columns() 130-134 The feature list, with or without the graph features (the ablation).
fit_quantile_model() 139-144 One XGBoost model that outputs all 23 quantiles at once (quantile loss), 150 trees, depth 4.
predict_quantiles() 147-148 Predicts and sorts each row's quantiles (so they never cross).
usable() 151-153 Drops features that are empty in the training rows.
seasonal_naive() 156-160 The bar to beat: "same week last year", with a range taken from its past errors.
prob_exceed() 163-175 Turns 23 quantiles into the probability of exceeding a threshold, by interpolating the quantile curve.
surge_thresholds() 178-183 Each unit's 90th percentile of 4-week incidence, computed from training weeks only.
to_cases() 188-189 Back from log incidence per 100,000 to case counts.
wis() 192-202 The weighted interval score (Bracher et al., 2021): rewards narrow ranges that contain the truth and penalises misses in proportion to how far out they are.
coverage() 205-208 Whether the outcome fell inside the 50% or 90% range.
refit_dates() 213-214 Refit every 13 weeks from January 2018 to December 2019 (8 refits).
rolling_origin() 217-254 The honest test. At each refit date: re-learn the graph and thresholds on past data, train on rows whose target is before the refit date, forecast every week until the next refit. Fits the model with and without graph features; when a window's graph has no links, the two are identical, so the second fit is skipped.
score() 257-285 WIS, error and coverage of every forecast for all three models, plus an online conformal 90% band (built only from errors of forecasts already past) as a check.
summarise() 288-304 Averages by horizon and overall: WIS, relative WIS vs seasonal naive, graph vs no-graph, coverage.
surge_calibration() 307-319 Brier score of R, the base rate, and a reliability table (when R says x, how often did a surge happen).
fit_at() 324-338 Trains all models on data up to a storm's landfall week (never past 2019), for the scenarios.
predict_at() 341-368 Forecasts every province from that week; optional overrides replace the storm features (shifted tracks); computes R and the per-driver SHAP contributions shown on the dashboard.

4.12 bantay/access.py

Layer 3: travel time to the nearest hospital over roads and ferries, before and during a storm.

Block Lines Explanation
PBF, ROADS, SPEED 31-38 The OpenStreetMap file, the cached road graph, and assumed travel speeds per road class (links at 80% of their road). Speeds are a tunable assumption, tested in the sensitivity analysis.
WALK_KMH, MAX_SNAP_KM, LAT0 38-39 Walking 5 km/h from a home to the road, at most 5 km; a reference latitude for fast km conversions.

11. Glossary

Term Meaning
R Surge probability: chance the next 4 weeks' incidence exceeds the province's 90th percentile.
A Access loss: share of a province's people who lose their route to a hospital in the storm.
P Priority = R x A.
Unit One of the 85 harmonised 2016-2020 provinces (NCR is split into its 4 districts).
Incidence Cases per 100,000 people.
Rolling origin Testing a forecaster as if in real time: train on the past, forecast forward, move the cut-off forward.
WIS / relative WIS Weighted interval score of a forecast range (lower is better); relative WIS < 1 means better than the seasonal-naive baseline.
Seasonal naive "Same week last year", the baseline forecast.
Quantile A forecast at a probability level; 23 of them describe the full range.
Coverage How often the truth falls inside a stated range (90% range should catch ~90%).
Brier score Error of a probability forecast (lower is better).
PCMCI+ A causal-discovery algorithm for time series that keeps a link only if it survives conditioning on other series and their pasts.
FDR / Benjamini-Hochberg A correction that controls the share of false links when testing thousands of pairs.
Sentinel / PageRank / Louvain A province others follow (scored with PageRank); groups of provinces that move together (Louvain).
Gale swath Area that saw gale-force (34-knot) winds along the track.
Shifted track The same storm moved north/south/east/west, for "what if" scenarios.
NOAH hazard proxy Using flood-hazard maps instead of observed flood to decide which roads close; an upper bound.
Sentinel-1 Radar satellite that sees flood through clouds; our observed-flood source (a lower bound).
EMS Copernicus Emergency Management Service flood maps; used to check Sentinel-1.
Dijkstra Shortest-path algorithm; run from all hospitals at once to get each place's nearest-hospital time.
Crosswalk A table mapping one set of place codes or names onto another.
Manifest data/raw/MANIFEST.csv: every raw file with size and checksum.
