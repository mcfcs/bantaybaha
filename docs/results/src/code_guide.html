1. The big picture

Bantay-Baha answers two questions for a typhoon track: where will dengue surge (R) and who loses their route to a hospital (A). Priority is P = R x A, and simple rules turn R and A into an action tier per province.

 download_data.py / download_gee.py / sync_data.py  ->  data/raw/            (21+ sources, MANIFEST.csv)
                                                          |
 scripts/build.py                                         v
   crosswalk  units.py       126 dengue units -> 85 harmonised provinces       (data/crosswalks/, units.gpkg)
   panel      panel.py       one row per province per week: cases, rain, rivers, storms, flood     (panel.parquet)
                uses dengue.py, storms.py, rain.py, rivers.py, grids.py, flood.py
   leadlag    leadlag.py     PCMCI+ lead-lag graph, sentinels, communities
   forecast   forecast.py    quantile XGBoost + ablations, rolling-origin test, WIS, calibrated surge risk R
   ensemble   forecast.py    re-score with any bench_<model>.parquet + their median ensemble (no refit)
   scenarios  scenarios.py   4 typhoons x 15 tracks: R (forecast) x A (access.py: network + raster) -> P, tiers
   catalog    scenarios.py   observed track of every other 2016-2020 storm whose gale swath reaches land
   app        (simplified map)
   lepto      lepto.py       leptospirosis lag analysis (national + 12 cities), typhoon event study
                                                          |
                                                          v   data/processed/app/
 app/streamlit_app.py      reads data/processed/app/ only     dashboard (with app/ui.py, sus.py, lepto_tab.py)
 scripts/benchmark_*.py    separate GPU venv: bench_<model>.parquet  ->  build.py ensemble
 scripts/make_results.py   reads data/processed/           ->  docs/results/ (report, slides, demo script, this guide)

python scripts/build.py runs all stages in this order (crosswalk panel leadlag forecast ensemble scenarios catalog app lepto); build.py panel forecast runs only those. Four rules shape the whole codebase:

  • Missing data never stops a build. Every stage checks its inputs with config.have() / config.missing(); missing inputs leave columns empty (NaN) and are listed in data/processed/status.json. Re-running after the files arrive picks them up with no code change. Nothing is ever filled with fake numbers.
  • No look-ahead. Forecasts are tested by rolling origin (train on the past, predict the future, move forward); the graph, the surge thresholds and the calibration of R are re-learned inside each training window. A Sentinel-1 flood map is used only from the week its last image exists (landfall + S1_AFTER_DAYS).
  • Heavy work happens in the build, not the dashboard. The dashboard only reads small pre-computed files, so it answers in seconds.
  • Optional outputs slot in. The dashboard and the documents show a section only when its file exists, so a partial build still renders.

2. Entry points (.bat files)

File What it does
setup.bat Team setup: creates the venv at %USERPROFILE%\.venvs\bantay-baha (outside OneDrive so it isn't synced), installs requirements.txt, registers the Jupyter kernel "Python (bantay-baha)", signs in to Google once (earthengine authenticate) if there are no saved credentials, then runs scripts/sync_data.py pull to copy data/raw/ from the team bucket (source names given to setup.bat are passed on). Skips existing non-empty files; streams to name.part and renames only when complete (an interrupted run never leaves a half file that looks finished); retries 3 times with back-off; with binary=True refuses an HTML page (a quota or login page) masquerading as a file.
drive_listing() 128-130 Lists a public Google Drive folder by parsing its embedded-view HTML (no API key needed).
fetch_drive() 133-135 Downloads a Drive file via drive.usercontent.google.com with confirm=t, which skips the virus-scan page Drive shows for files over 100 MB.
pull_static() 138-139 Fetches every (url, filename) of one STATIC source.
pull_ems() 142-149 Scrapes each EMS activation page for *_vector.zip links and downloads the ones matching the filter (EMSR312 delineation packages; all of EMSR478).
pull_noah() 152-165 Downloads the NOAH readme, metadata and licence, then every province zip in the 5-yr and 25-yr folders; a failed province is recorded in PARTIAL and the rest continue.

scripts/download_gee.py (Google Earth Engine sources)

Needs a registered Earth Engine project (--project <id>). Pulls IMERG rainfall, the MAP friction surface, Global Flood Database events, a Sentinel-1 scene inventory and the Sentinel-1 flood masks. Like download_data.py, every file goes to <name>.part first and is renamed when complete, and each source is added to the manifest as soon as it finishes.

Block Lines Explanation
Imports, ROOT, RAW, BBOX 20-36 Same layout as download_data.py; imports its write_manifest so GEE files land in the same manifest.
TYPHOONS, IBTRACS_NAMES 39-46 The four backtest storms: landfall dates (for before/after windows) and their IBTrACS names (to find the track).
S1_BEFORE, S1_AFTER 49-50 The Sentinel-1 windows in days from landfall: before = days -30 to -3, after = days 0 to +10. config.S1_AFTER_DAYS must equal the end of the after window, because a flood map only exists once its last image does (section 4.9).
done() 53-58 True (and prints skip) if the file is already on disk and not empty; otherwise creates its folder. Every puller calls it first, so re-runs skip finished files.
save() 61-64 Writes bytes to <name>.part, then renames: an interrupted run never leaves a half file that a later run would skip.
write_csv() 67-72 Writes a table (list of dicts) as CSV through save().
download_image() 75-95 Asks Earth Engine for a GeoTIFF of an image over a region at a scale and downloads it. EE computes the image on request and sometimes answers 503/429, so it retries up to 4 times with a fresh URL and a growing pause. Unzips when EE returns a zip. Skips files already on disk.
pull_imerg() 98-114 For each month 2016-2020, turns half-hourly IMERG (mm/h) into daily totals (mean x 24) and stacks the days as bands of one GeoTIFF per month.
pull_map_friction() 117-123 Downloads the Malaria Atlas Project 2019 friction surfaces (motorised and walking), about 1 km.
pull_gfd() 126-135 Writes a table of Global Flood Database events that intersect the Philippines (dates, cause, deaths). Context only: its events stop in 2017.
pull_sentinel1() 138-156 Lists every Sentinel-1 IW VV scene from 24 days before to 14 days after each landfall (no imagery), used to plan the flood mapping.
track_tiles() 159-174 Picks the 1-degree tiles of the Philippine box whose centre is within ~350 km (plus half a tile) of a storm's track (reads the local IBTrACS file), so we only process tiles the storm could have flooded.
s1_flood_image() 177-212 The flood-mapping recipe, computed on Google's servers. For each relative orbit (same satellite geometry) that imaged the tile both before and after landfall: before = median of the smoothed VH backscatter over the S1_BEFORE days, after = darkest smoothed image of the S1_AFTER days; a pixel is new flood when VH drops by at least 3 dB and ends at or below -18 dB (water is radar-dark). Floods from all orbits are combined; permanent water (JRC), slopes over 5 degrees and specks under 8 pixels are removed. Output: 1 = new flood, 0 = dry, 255 = no data or sea. Why not plain UN-SPIDER? Its after/before ratio on dB values under-detects surfaces that were already dark: at Tuguegarao it caught 2 of 12 EMS-flooded sample points, this rule 6 of 12.
STORM_FILTER, pull_s1_flood() 215-237 Loops over storms (or only those given with --storms) and their tiles; builds the flood image per tile and downloads it at 100 m. Tiles no orbit covered are reported as none and skipped.
PULLERS, main block 240-254 Command-line entry: initialises Earth Engine with the project, runs the chosen pullers and writes the manifest per source.

6.5 Tests: tests/

Two kinds of tests. Pipeline unit tests check the documented rules of bantay/ and scripts/ on small hand-built inputs (a few units, a 4-node road, a 5 x 5 GeoTIFF, a temporary CSV); they need no build and no network. Build tests read the real outputs: the dashboard tests (test_app.py, test_e2e.py) and the output invariants (test_build_outputs.py, test_make_results.py, marker data); they skip when the outputs are missing. Build tests check facts fixed by the data (126 dengue units, 85 units, 262 weeks) and consistency between outputs (ranges, leak-free dates, same-row scoring, ensemble members), never numbers that come from a fitted model, so model improvements do not break them. No test writes into data/: the status registry goes to a temporary file, downloads go to tmp_path, and a session check fails the run if any file under data/ changed. Usability answers go to a temporary file; screenshots and videos land in tests/artifacts/ (git-ignored). Install requirements-dev.txt and python -m playwright install chromium once, then:

python -m pytest tests                            # everything (~1.5 min): unit, build outputs, AppTest, Playwright
python -m pytest tests -m "not e2e"               # no browser (~40 s)
python -m pytest tests -m "not e2e and not data"  # pipeline unit tests + AppTest, no build-output invariants
python -m pytest tests -m data                    # build-output invariants only
python tests/capture.py                           # refresh docs/results/figures/dashboard.png + record the demo video

A test marked xfail(strict=True) documents a known bug in the code: it fails today, and the suite turns red once the bug is fixed, so the marker is removed together with the fix.

8. Benchmark models

The proposal compares XGBoost with three outside models: Chronos-2 and TabPFN-TS (zero-shot foundation models) and MPNN-LSTM (a graph neural network). They are optional and run outside the build:

  • A separate venv. They need torch with CUDA, and their packages pin an older pandas than the main venv, so they live in %USERPROFILE%\.venvs\bantay-bench (Python 3.12). requirements-bench.txt holds the exact install commands and the tested versions. Model weights download into the user cache on first run; no token or account is needed.
  • The output contract (benchmark_common.py). Each model writes data/processed/app/bench_<model>.parquet: one row per (unit, forecast origin, horizon 1-4) of the XGBoost evaluation (exactly the rows of eval_scores.parquet), with q = the 23 FluSight quantiles of log1p(incidence per 100k), ascending; and bench_<model>.json with versions, device, runtime, inputs and notes. Every input at an origin must come from weeks up to that origin.
  • Then benchmark_score.py writes bench_summary.csv (headline models and variants, with median WIS), and build.bat ensemble re-scores everything and builds the median ensemble without refitting XGBoost.
  • The forecast.BENCH_MODELS rule. Only chronos2, tabpfn_ts and mpnn_lstm enter the model table and the median ensemble. Every other bench_* file (chronos2_log1p, mpnn_lstm_border, ...) is a variant: scored by benchmark_score.py, listed on the dashboard as "not used", ignored by the build so it cannot tilt the ensemble. To make a new model a headline benchmark, add its name to BENCH_MODELS.

The storm scenarios always use XGBoost: the benchmarks take no storm-track input, so they can't score a shifted track.

11. Glossary

Term Meaning
R Surge probability: chance the next 4 weeks' incidence exceeds the province's 90th percentile.
Calibrated R / R raw The model's raw probability (R_raw) mapped by an isotonic fit to how often surges really happened, using past forecasts only. The calibrated value is R, used for P and the tiers.
A Access loss: share of a province's people who lose their route to a hospital in the storm.
Network / raster method Two ways to compute travel time: the road and ferry graph (main) and the MAP friction surface (check). A_lo / A_hi (and P_lo / P_hi) span the two.
P Priority = R x A.
Tier The provisional action rule: deploy mobile clinics, pre-position supplies, or monitor.
Unit One of the 85 harmonised 2016-2020 provinces (NCR is split into its 4 districts).
Incidence Cases per 100,000 people.
Rolling origin Testing a forecaster as if in real time: train on the past, forecast forward, move the cut-off forward.
WIS / relative WIS Weighted interval score of a forecast range (lower is better); relative WIS < 1 means better than the seasonal-naive baseline.
Seasonal naive "Same week last year", the baseline forecast.
Ablation The same model with a group of features removed (no graph, no rain/river/storm/flood), to see what that group adds.
Benchmark / median ensemble Outside models scored on the same rows (Chronos-2, TabPFN-TS, MPNN-LSTM); the ensemble is the median of their and XGBoost's quantiles.
Quantile A forecast at a probability level; 23 of them describe the full range.
Coverage How often the truth falls inside a stated range (90% range should catch ~90%).
Brier score Error of a probability forecast (lower is better).
PCMCI+ A causal-discovery algorithm for time series that keeps a link only if it survives conditioning on other series and their pasts.
FDR / Benjamini-Hochberg A correction that controls the share of false links when testing thousands of pairs.
Sentinel / PageRank / Louvain A province others follow (scored with PageRank); groups of provinces that move together (Louvain).
Gale swath Area that saw gale-force (34-knot) winds along the track.
Shifted track The same storm moved north/south/east/west, for "what if" scenarios.
Storm catalogue Every other 2016-2020 storm whose gale swath reached land, scored on its observed track with the NOAH proxy.
NOAH hazard proxy Using flood-hazard maps instead of observed flood to decide which roads close; an upper bound.
Sentinel-1 Radar satellite that sees flood through clouds; our observed-flood source (a lower bound).
EMS Copernicus Emergency Management Service flood maps; used to check Sentinel-1.
HRSL Meta's High Resolution Settlement Layer: counts of children under 5 and people aged 60+, used for the vulnerable people cut off.
Dijkstra Shortest-path algorithm; run from all hospitals at once to get each place's nearest-hospital time.
IRR / distributed lag Incidence rate ratio (1 = no change); a distributed-lag model fits several weeks of lagged rain together.
Event study / placebo Comparing cities inside and outside a storm's swath around landfall; the weeks before landfall should show no difference.
SUS System Usability Scale: ten statements scored 0-100; about 68 is average.
Crosswalk A table mapping one set of place codes or names onto another.
Manifest data/raw/MANIFEST.csv: every raw file with size and checksum.
